# 07 测试与验收计划

## 1. 测试分层

| 层 | 范围 | 工具 | 说明 |
| --- | --- | --- | --- |
| 单元测试 | 各 internal 包 | `go test` | 纯逻辑验证，不依赖网络 |
| 集成测试 | 协议↔服务端、客户端↔服务端 | `go test`（本地起监听） | 真实 TCP 连接 |
| 端到端测试 | 多节点集群 + 迁移 + 控制台 API | 脚本（`test/e2e.sh`）+ 手动验收 | 演示级验证 |
| 规模校验 | 代码行数/文件数 | `wc -l` / `find` | 硬性约束 |

测试代码（`*_test.go`）**不计入** 2000~2200 行与 20~25 文件的约束（见 05 文档）。

## 2. 单元测试用例

### 2.1 internal/hash（一致性哈希）
- 同一 key 多次 `Get` 结果一致（确定性）；
- 同一节点 `Add` 两次 → 去重/报错；
- 3 节点写入 10000 键，各节点键数偏差 < 20%；
- 3→4 节点：迁移比例 ≈ 25%（±5%），其余 key 归属不变（单调性）；
- 空环 `Get` → 返回空字符串（不 panic）。

### 2.2 internal/cache（存储 + TTL + LRU）
- Set/Get/Del/Exists 基础语义；
- TTL 到期后 GET 返回未命中且条目被惰性删除；
- 清扫器在模拟时钟下删除过期条目并归还容量；
- LRU：容量 3 写入 4 键 → 最久未使用被淘汰；GET 命中后刷新次序；
- LRU 淘汰与 TTL 清扫并发下不变量保持（map 与链表一致）；
- FLUSH 清空全部；KEYS 前缀过滤与分页。

### 2.3 internal/protocol（编解码）
- 帧编解码往返一致（含空值、最大长度边界）；
- 半包：分两次写入，解码器正确拼帧；
- 粘包：一次写入两帧，解码出两条；
- 长度超限（key > 256B / value > 1MB）→ 返回 ERR_BAD_ARG；
- Magic 错误 → 解码失败。

### 2.4 internal/cluster（成员表 / 迁移）
- 成员表增删与序列化往返；
- 迁移状态机：PREPARING→MIGRATING→DONE；
- 模拟"迁移中环变化"→ 迁移中止并重算；
- 迁移失败重试与进度统计正确。

## 3. 集成测试用例

| 用例 | 步骤 | 预期 |
| --- | --- | --- |
| 单节点 CRUD | 起一个服务端，用 client SET/GET/DEL | 结果正确，TTL 生效 |
| 协议健壮性 | 原始 TCP 发送损坏帧/未知命令 | 返回错误码，连接不断开 |
| MOVED 重定向 | 客户端环视图过期（手动移除节点后直连旧节点写） | 返回 MOVED，客户端更新视图并成功 |
| 优雅下线 | 3 节点写入数据 → LEAVE 1 节点 | 数据全部可读（迁移完成） |
| 心跳故障 | kill 1 节点进程 | 约 3s 后被判定故障，成员表更新，不阻塞其他节点 |

## 4. 端到端验收用例（对照需求）

| # | 需求 | 验收步骤 | 通过标准 |
| --- | --- | --- | --- |
| 1 | R2 一致性哈希分片 | 3 节点起集群，写入 10000 键，`STATS` 查看各节点键数 | 各节点键数偏差 < 20% |
| 2 | R3 TCP 协议 | 用 `nc` 发送原始 SET/GET 帧 | 返回正确响应帧 |
| 3 | R4 TTL 过期 | SET EX 2，等待 3s 后 GET | 未命中；`STATS` 中 expired_keys 增加 |
| 4 | R5 LRU 淘汰 | 容量设为 100，写入 150 键 | 键数 ≤ 100，`evicted_keys` 增加 |
| 5 | R6 节点加入迁移 | 3 节点写入 10000 键 → 添加第 4 节点 | 迁移约 25% 键；全部键仍可读 |
| 6 | R6 节点下线迁移 | 3 节点写入 → 优雅下线 1 节点 | 数据迁移至剩余节点，全部可读 |
| 7 | F9 控制台 | 打开 `http://127.0.0.1:8080` | 拓扑/指标/迁移进度实时可见，节点增删可操作 |
| 8 | 规模约束 | 执行 05 文档 §5 命令 | 行数 ∈ (2000, 2200)，文件数 ∈ (20, 25) |

## 5. 规模验收命令（最终交付前必须通过）

```bash
# 1) 行数（不含测试）：2000 < N < 2200
N=$(find . -name '*.go' ! -name '*_test.go' ! -path './web/*' | xargs wc -l | tail -1 | awk '{print $1}')
[ "$N" -gt 2000 ] && [ "$N" -lt 2200 ] && echo "PASS 行数=$N" || echo "FAIL 行数=$N"

# 2) 文件数：20 < M < 25
M=$(find . -name '*.go' ! -name '*_test.go' ! -path './web/*' | wc -l | tr -d ' ')
[ "$M" -gt 20 ] && [ "$M" -lt 25 ] && echo "PASS 文件数=$M" || echo "FAIL 文件数=$M"

# 3) 编译与静态检查
go build ./... && go vet ./... && gofmt -l . | grep -v '^$' || true

# 4) 测试（测试代码不计入规模约束）
go test ./... -count=1
```

## 8. 风险与预案

| 风险 | 预案 |
| --- | --- |
| 行数超上限 | 合并协议编解码文件（-80 行）或精简注释型导出注释 |
| 行数不足下限 | 拆分命令处理、补迁移续传/进度上报、补 KEYS 分页（+60~100 行） |
| 文件数越界 | 控制在 21~24；不新增无职责文件 |
| 迁移并发 bug | 迁移相关逻辑集中测试；先写后删语义单测覆盖 |
| 心跳误判 | 阈值可配置；演示时手动 kill 进程而非断网模拟 |
