## 2. 分层设计

| 层 | 包 | 职责 | 依赖 |
| --- | --- | --- | --- |
| 入口层 | `main.go` | 解析参数、装配依赖、启动各模块、优雅退出 | 全部 internal |
| 配置层 | `internal/config` | 命令行/环境变量解析、校验、默认值 | 无 |
| 协议层 | `internal/protocol` | 帧编解码、命令常量、错误码 | 无 |
| 服务层 | `internal/server` | TCP 监听、连接会话、命令分发、归属校验 | protocol, cache, cluster, metrics |
| 存储层 | `internal/cache` | KV 存储、条目模型、TTL 清扫、LRU 淘汰、缓存门面 | 无（metrics 可选） |
| 哈希层 | `internal/hash` | 一致性哈希环（虚拟节点、查找） | 无 |
| 集群层 | `internal/cluster` | 成员表、JOIN/LEAVE、环重建、数据迁移、心跳 | hash, cache, protocol, client(迁移用) |
| 客户端层 | `internal/client` | 连接池、命令发送、哈希路由、MOVED 跟随 | protocol, hash |
| 指标层 | `internal/metrics` | 计数器/直方图、快照导出 | 无 |
| Web 层 | `internal/web` | REST API、静态资源 embed、控制台后端 | cache, cluster, metrics |

依赖方向严格自上而下，禁止反向依赖（如 cache 不依赖 cluster）。

## 4. 关键数据流

### 4.1 客户端写入（路由 → 服务端 → 存储）

```
Client.Set(key, value)
  → ring.Get(key) = node2（客户端本地环）
  → conn(node2).Send(SET ...)
  → node2: protocol.Decode → handler.dispatch
  → cluster.owns(key)?  否 → 回 MOVED node3 → client 更新环视图并重试
  → cache.Set(key, value, ttl)
      → store 插入 / LRU 腾位 / TTL 登记
  → response(OK) → client
```

### 4.2 节点加入（集群事件 → 迁移）

```
Node4 JOIN → seed 广播 MEMBERS_UPDATE
  → 各节点 cluster.RebuildRing()
  → nodeX.PREPARING：扫描本地，找出"新环不归自己"的 key 集合
  → nodeX.MIGRATING：分页发送 MIGRATE → 目标节点 cache.Set（幂等）
  → 源节点 DEL 已迁 key → 进度上报 → DONE
```

### 4.3 Web 控制台数据流

```
浏览器 → GET /api/status → web 聚合本节点 cache + metrics + cluster 视图
  → 返回 JSON（节点列表、键数、命中率、迁移进度）
  → 前端定时轮询（2s）渲染仪表盘
浏览器 → POST /api/nodes （添加节点/下线节点）
  → web 调用 cluster.Join/Leave → 触发真实迁移
```

## 5. 部署形态

| 形态 | 说明 | 用途 |
| --- | --- | --- |
| 单节点 | 一个进程，`-addr 127.0.0.1:7301` | 开发调试、单元测试 |
| 多节点（本机演示） | 同一机器多个进程，不同端口 | 演示分片、迁移、控制台 |
| 多节点（跨机） | 不同机器，`-seed` 指向已知节点 | 真实分布式部署 |

所有节点地位对等（无中心节点），seed 仅用于引导加入。

## 6. 技术选型

| 项 | 选择 | 理由 |
| --- | --- | --- |
| 语言 | Go 1.21+ | 并发模型契合、单二进制 |
| 依赖 | 仅标准库 | 无网络依赖、构建简单、符合规模约束 |
| 哈希 | `hash/crc32`（IEEE） | 标准库、分布均匀、确定性 |
| 协议 | 自定义二进制（大端） | 低开销、可控性 |
| 前端 | 原生 HTML/CSS/JS + `embed` | 无需构建链，Go 直接内嵌 |
| 并发模型 | goroutine per 连接 + 存储互斥锁（细粒度分桶锁） | 简单且性能足够演示 |

## 7. 并发与一致性设计

- **存储并发**：分桶锁（如 64 个桶，`key % 64` 定位桶），读写互斥、桶间并行；
- **LRU/TTL 与存储的一致性**：三者共用同一把桶锁（或同一互斥体），保证"条目存在于 map ⇔ 存在于 LRU ⇔ TTL 登记"不变量；
- **迁移并发**：迁移扫描与读写共用桶锁，但逐条加锁（扫描批次内对单 key 操作），避免长锁阻塞业务；
- **成员表一致性**：广播采用"每个节点独立应用"模型，允许短暂不一致（以 MOVED 兜底）；演示版不做共识。
