# 06 前端界面设计（Web 控制台）

## 1. 定位与选型

- **定位**：简单运维/演示控制台——可视化展示集群拓扑、节点健康、缓存指标、键数据，并支持触发节点增减与查看真实迁移过程；
- **技术**：原生 HTML + CSS + JavaScript（无框架、无构建链），通过 `fetch` 调用 Go 提供的 REST API；
- **交付**：`web/index.html`、`web/style.css`、`web/app.js` 三个静态文件，由 `internal/web/server.go` 通过 `go:embed` 内嵌，访问 `http://<host>:8080/` 即得；
- **数据刷新**：前端每 2s 轮询 `/api/status`（简单轮询，避免引入 WebSocket 复杂度）。

## 2. 页面结构（单页应用）

```
┌──────────────────────────────────────────────────────────────┐
│  DCache 控制台            [节点: 3] [总键: 12,345] [命中率 92%] │  ← 顶栏摘要
├───────────────┬──────────────────────────────────────────────┤
│  侧边导航      │  主内容区                                     │
│  ① 仪表盘      │  ┌───────────────────────────────────────┐  │
│  ② 键管理      │  │ 节点卡片 ×N（健康/地址/键数/内存水位）   │  │
│  ③ 节点管理    │  └───────────────────────────────────────┘  │
│  ④ 命令测试台  │  迁移进度条 / 最近事件列表                    │
└───────────────┴──────────────────────────────────────────────┘
```

| 页面 | 内容 | 主要交互 |
| --- | --- | --- |
| ① 仪表盘 | 集群总览：节点卡片、每节点键数/命中率/QPS、迁移进度条、最近事件 | 轮询刷新 |
| ② 键管理 | 键列表（按节点/前缀过滤）、值预览、TTL 显示 | 查看、删除键、设置 TTL |
| ③ 节点管理 | 节点表格 + 添加/下线表单 | 添加节点（填 addr）→ 触发 JOIN + 真实迁移；下线节点 → 触发 LEAVE + 迁移 |
| ④ 命令测试台 | 命令输入框 + 结果输出区 | 向指定节点发送任意命令，展示原始响应 |

## 3. REST API 设计（internal/web）

| 方法 | 路径 | 说明 | 响应要点 |
| --- | --- | --- | --- |
| GET | `/api/status` | 集群总览 | `{nodes:[{name,addr,alive,keys,memory,hits,misses,qps}], totalKeys, hitRate, migration:{state,total,done}}` |
| GET | `/api/keys?node=&prefix=&page=` | 键列表（分页） | `{keys:[{key,ttl,valuePreview}], total}` |
| DELETE | `/api/keys/:node/:key` | 删除键 | `{ok:true}` |
| POST | `/api/keys/:node/:key/expire` | 设置 TTL | `{ok:true, ttl}` |
| GET | `/api/nodes` | 节点列表 | `[{name,addr,alive}]` |
| POST | `/api/nodes` | 添加节点（`{addr}`） | `{ok:true}`，后台触发 JOIN 与迁移 |
| DELETE | `/api/nodes/:addr` | 下线节点（优雅 LEAVE） | `{ok:true}`，后台触发迁移 |
| GET | `/api/migrate` | 迁移进度 | `{state,total,done,currentTarget,lastError}` |
| POST | `/api/cmd` | 命令测试台（`{node,cmd,args}`） | `{ok,result}` |
| GET | `/` | 静态页面（embed） | index.html |

## 4. 关键交互时序

### 4.1 添加节点（演示扩容与迁移）

```
用户点击"添加节点 127.0.0.1:7304"
  → POST /api/nodes {addr:"127.0.0.1:7304"}
  → web 调用 cluster.AddNode → 新节点 JOIN → 广播 → 各节点重建环
  → 各旧节点启动迁移（MIGRATING）
  → 前端轮询 /api/status 与 /api/migrate：
      仪表盘出现 node-4 卡片（键数从 0 增长）
      迁移进度条推进：done/total
      旧节点键数下降、新节点键数上升（约 1/4 数据）
  → 迁移 DONE → 提示"扩容完成"
```

### 4.2 下线节点（演示缩容与数据迁移）

```
用户点击 node-2 的"下线"
  → DELETE /api/nodes/127.0.0.1:7302
  → node-2 标记 LEAVING → 广播移除 → 各节点重建环
  → node-2 将数据迁移至新归属节点 → 完成后退进程
  → 仪表盘 node-2 卡片消失，其键数转移到其他节点
```

## 5. 前端文件职责

| 文件 | 职责 | 预估规模 |
| --- | --- | --- |
| `web/index.html` | 页面骨架：顶栏、侧边导航、四个视图容器 | ~120 行 |
| `web/style.css` | 深色简洁主题、卡片布局、进度条、状态指示灯 | ~180 行 |
| `web/app.js` | 路由切换、轮询、REST 调用、渲染（模板字符串）、迁移动画 | ~260 行 |

前端文件不计入 Go 代码行数/文件数约束（见 05 文档）。

## 6. 视觉规范

- 主题：深色背景（#1e1e2e）、强调色（#4f9cf9）、成功绿（#2ecc71）、故障红（#e74c3c）；
- 节点卡片：状态圆点（绿=健康 / 红=故障 / 黄=迁移中）、地址、键数、内存水位条；
- 迁移进度：进度条 + `done/total` 数字 + 状态文案（PREPARING/MIGRATING/DONE）；
- 移动端不做适配（演示工具定位）。

## 7. 可访问性

- 所有按钮/输入框带 label 与 placeholder；
- 轮询失败时显示"连接断开"横幅并自动重连，不白屏。
