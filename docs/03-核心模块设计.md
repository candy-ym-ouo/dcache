# 03 核心模块设计

本文档详述四个核心机制的设计：一致性哈希、LRU 淘汰、TTL 过期、数据迁移。

## 1. 一致性哈希（internal/hash）

### 1.1 设计要点

- **环结构**：`Ring` 维护一个有序虚拟节点表 `[]ringPoint{hash uint32, node string}`，按 hash 升序存储；
- **虚拟节点**：每个物理节点生成 `virtualCount`（默认 160）个虚拟节点，虚拟节点名 `fmt.Sprintf("%s#%d", nodeName, i)`；
- **哈希函数**：`crc32.ChecksumIEEE([]byte(name))`，均匀分布到 `[0, 2^32)`；
- **查找**：`Get(key)` → `crc32(key)` → 二分查找第一个 `hash >= h` 的点，越界则取表头（环回绕）；
- **增减节点**：`Add(node)` / `Remove(node)` 重建虚拟节点表并排序（演示版全量重建，节点数少时开销可忽略）。

### 1.2 单调性验证

- 节点数从 3 → 4：仅约 25%（`K/(N+1)`）的 Key 改变归属；
- 证明思路：每个 Key 的归属仅由环上其顺时针后继虚拟节点决定，移除/新增的虚拟节点只影响其环上相邻区间的 Key。

### 1.3 数据结构

```go
type Ring struct {
    mu        sync.RWMutex
    points    []uint32      // 有序虚拟节点哈希
    virtuals  map[uint32]string // hash -> 物理节点名
    virtualCount int        // 每节点虚拟节点数（默认 160）
}
func (r *Ring) Add(node string)      // 增加节点及其虚拟节点
func (r *Ring) Remove(node string)   // 移除节点
func (r *Ring) Get(key string) string // 返回 key 的归属节点名
func (r *Ring) NodeCount() int
```

### 1.4 均衡性目标

单节点键数偏差 < 20%（3 节点、10000 键、160 虚拟节点时，理论偏差约 5%）。

## 2. LRU 淘汰（internal/cache/lru.go）

### 2.1 设计要点

- **数据结构**：`map[string]*list.Element` + `container/list`（双向链表），头部=最近使用，尾部=最久未使用；
- **容量**：以"键数量"为上限（`MaxKeys`，默认 10000），可选字节数上限（二期）；
- **操作**：
  - `Get(key)`：命中 → 移动到头部；
  - `Put(key, item)`：已存在 → 更新值并移动到头部；不存在 → 若满则 `Evict()` 直到有空位，然后插入头部；
  - `Delete(key)`：从 map 与链表移除；
  - `Evict()`：移除尾部条目，返回被淘汰的 key（供外部计数与清理 TTL 登记）。

### 2.2 淘汰策略

- 纯 LRU（最近最少使用），不区分条目是否带 TTL；
- 被 TTL 清扫器删除的条目自动从 LRU 移除（共用锁保证不变量）。

### 2.3 数据结构

```go
type LRU struct {
    mu      sync.Mutex
    maxKeys int
    items   map[string]*list.Element // key -> 链表元素
    ll      *list.List               // 元素值为 *Item
}
type Item struct { // 见 3.3 节，与 LRU 共用
    Key      string
    Value    []byte
    ExpireAt time.Time // 零值表示永不过期
    ele      *list.Element // LRU 内部指针（不导出）
}
```

## 3. TTL 过期（internal/cache/ttl.go）

### 3.1 过期语义

- `Item.ExpireAt`：绝对过期时间戳；零值 = 永不过期；
- `Set(key, value, ttl)`：`ttl <= 0` 表示永不过期（除非 ttl==0 视为立即过期，由命令层语义决定：SET 不带 EX 即永不过期）；
- `Expire(key, seconds)`：设置/重置；`Persist(key)`：清空过期时间。

### 3.2 惰性删除

所有读路径（GET/EXISTS/TTL）进入存储层前调用 `isExpired(item)`：`!item.ExpireAt.IsZero() && now.After(item.ExpireAt)` → 删除并返回未命中。保证**用户不可见过期数据**。

### 3.3 主动清扫

- **调度**：后台 goroutine，`time.Ticker`，间隔 `-sweep-interval`（默认 500ms）；
- **渐进式扫描**：存储按 64 个桶分片，清扫器每轮扫描一个桶内的一个窗口（如每个桶每次最多扫 256 条），一轮遍历全部桶后回到起点；避免大容量下长时间持锁；
- **动作**：删除过期条目、归还 LRU 容量、累加 `expiredKeys` 指标；
- **优雅退出**：通过 context 取消信号停止清扫器。

### 3.4 命令语义

| 命令 | 语义 |
| --- | --- |
| `SET k v` | 永不过期 |
| `SET k v EX 30` | 30 秒后过期 |
| `EXPIRE k 30` | 对已存在键设置过期（覆盖原值） |
| `TTL k` | 剩余秒（向上取整）；不存在/已过期 → -2；无过期 → -1 |
| `PERSIST k` | 移除过期时间 |

## 4. 数据迁移（internal/cluster/migrate.go）

### 4.1 触发与状态机

```
事件（成员表变化）→ Migrator.Start(newRing)
状态：IDLE → PREPARING → MIGRATING → DONE（异常 → IDLE/重算）
```

- **PREPARING**：快照记录 `oldRing`（变更前）与 `newRing`（变更后）；枚举"旧环归属自己、新环归属他人"的候选 key（通过扫描本地存储 + 新环判定）；
- **MIGRATING**：分页扫描（每批 `pageSize`=100 条），对候选 key：
  1. 计算 `newRing.Get(key)` → `target`；
  2. `target == self` → 跳过（键留在本节点）；
  3. 否则发送 `MIGRATE key value ttlRemain` 给 target（通过内部 client 连接）；
  4. target 收到后执行幂等 `Set`（保留剩余 TTL），返回 OK；
  5. 源节点收到 OK 后 `Del(key)`（**先写后删**，防止丢数据）；
  6. 更新进度 `migrated/total`；
- **DONE**：全部完成，上报 `MigrationDone`，回到 IDLE。

### 4.2 容错

| 场景 | 处理 |
| --- | --- |
| 迁移中环再变 | `newRing` 版本号变化 → 中止当前批次 → 回到 PREPARING 用最新环重算 |
| 目标不可达 | 该批暂停并重试（退避）；连续失败超过阈值 → 触发目标故障判定 |
| 源节点宕机重启 | 重启后依据当前环重新 PREPARING；已迁 key 因幂等写入安全 |
| 目标已存在同 key | 直接覆盖（幂等 SET 语义） |
| key 带 TTL | 迁移时计算 `ttlRemain = ExpireAt - now`，目标节点按剩余时间重建 |

### 4.3 进度与查询

- `Migrator.Status()` → `{state, total, done, currentTarget, lastError}`；
- 供 `STATS` 命令与 Web 控制台展示；迁移期间节点仍正常服务读写。

### 4.4 为什么"先写后删"

若先删后写且迁移失败，数据永久丢失；先写后删保证任意时刻至少一份数据可读（读旧节点或读新节点），满足演示版最终一致。

## 5. 心跳与健康检查（internal/cluster/heartbeat.go）

- 每节点每 `-heartbeat-interval`（默认 1s）向成员表内其他节点发送 `PING`；
- 对方回 `PONG`；连续 `-fail-threshold`（默认 3）次未收到 → 判定故障；
- 故障处理：从成员表移除 → 广播 → 各节点重建环 → 触发迁移（新归属节点接管；数据不可达按 01 文档 4.7 取舍处理）；
- 心跳失败重试带 jitter，避免同步风暴。
