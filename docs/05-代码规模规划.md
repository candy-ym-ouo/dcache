## 3. 容差与保障规则

- **目标总量 2150 行**，实现时允许每个文件 ±10 行浮动；
- **硬性校验**：最终 `wc -l`（排除 `_test.go` 与 `web/`）必须落在开区间 `(2000, 2200)`，否则按 §5 调整；
- **文件数**：22 个（`internal` 20 个 + `main.go` 1 个 + 顶层 1 个）；如需增减，保持总数在 21~24，且每个文件仍承担独立职责；
- **禁止注水**：不得通过空行/注释堆砌行数；行数由真实逻辑自然产生。若实现后不足 2000 行，优先补充合理功能（如 KEYS 分页、迁移进度上报、控制台辅助 API），而非填充空行；
- **测试代码独立**：`*_test.go` 文件不计入上述行数与文件数约束。

## 4. 每个文件的职责边界（防止重复实现）

| 文件 | 明确的"不做"边界 |
| --- | --- |
| main.go | 不含业务逻辑，仅装配 |
| protocol/* | 不接触存储与集群，仅字节流编解码 |
| server/handler.go | 只做分发与组装，不直接操作 LRU/TTL 细节（走 cache 门面） |
| cache/* | 不感知集群与网络；store/ttl/lru 通过 cache.go 门面对外 |
| hash/ring.go | 纯数据结构，不涉及网络 |
| cluster/migrate.go | 迁移读写走 cache 门面 + client 发送，不直接解析协议 |
| web/handlers.go | 只做 HTTP 适配，业务复用 cache/cluster/metrics |

## 5. 规模统计与校验命令

```bash
# Go 代码行数（不含测试）——目标 (2000, 2200)
find . -name '*.go' ! -name '*_test.go' ! -path './web/*' | xargs wc -l | tail -1

# Go 代码文件数——目标 (20, 25)
find . -name '*.go' ! -name '*_test.go' ! -path './web/*' | wc -l

# 测试文件（不计入约束，另行统计）
find . -name '*_test.go' | wc -l
```

若超出上限：优先合并 `protocol/request.go` 与 `protocol/response.go` 为 `protocol/frame.go`（-80 行）；
若低于下限：将 `server/handler.go` 中的命令处理拆出 `server/commands.go`（+100 行左右），或为 `cluster/migrate.go` 增加迁移续传逻辑（+60 行左右）。

## 6. 代码规范

- 包名小写单数；导出类型/函数带注释；
- 错误处理显式返回，不吞错；关键路径记录日志；
- 并发访问统一走 `sync.Mutex`/`RWMutex`，锁粒度见 02 文档 §7；
- 常量（命令码、错误码、默认端口等）集中在 protocol/command.go 与 config.go，禁止魔法数；
- 全部代码 `gofmt` 格式化，`go vet` 零告警。
